# EasyMic 自动化测试

测试程序集：`Eitan.EasyMic.Tests`，运行模式：Unity EditMode。参数化测试的每组参数按独立用例统计。这里列的是行为覆盖范围，不代表逐行或分支覆盖率达到 100%。

## 运行

项目使用 Unity 2021.3.45f2。可以在 Unity Test Runner 中选择该程序集运行，也可以在仓库根目录运行：

```sh
python3 Tools/run_unit_tests.py \
  --unity /Applications/Unity/Hub/Editor/2021.3.45f2/Unity.app/Contents/MacOS/Unity
```

脚本在临时目录创建空的 Unity 工程，复制 EasyMic 包和依赖清单，执行整个测试程序集。它不会打开真实麦克风或扬声器，也不会改动当前编辑器工程。首次运行需要 Unity 许可证和 UPM 依赖下载。导入的示例场景、APM 示例自动测试入口和其他本地编辑器脚本不会复制进去。

结果默认保存在仓库的 `output/test-results/easymic-editmode.xml` 和 `easymic-editmode.log`。脚本要求所有发现的用例通过；零测试、失败、跳过、缺失报告或 Unity 异常退出都会返回非零状态。可以用 `--filter Eitan.EasyMic.Tests.AudioEventPumpContractTests` 定向执行，用 `--keep-project` 保留验证工程。

## 已补的回归保护

- 事件长度与 capture frameCount 的整数溢出；事件泵重启后主线程队列中的旧通知失效。
- 录音处理器工厂失败时释放已创建资源；被拒绝的处理器不占用注册键，允许重试。
- 原生处理器重新初始化时释放旧分配；重新初始化再释放后不继续处理。
- 原生 DSP 的 NaN/Infinity 控制参数在写入状态前抛出 `ArgumentOutOfRangeException`，参数原值保持不变；空初始化上下文提前拒绝。
- `Stop(clearClip: true)` 和会话释放清理 clip 引用；保存录音时非法路径返回失败。
- 全局输出停止后 clip 馈送线程退出，不再从后台线程重启设备或读取 Unity 设置；关键词提示音测试隔离并清理其播放句柄。
- 设备原生格式变化触发更新事件；watcher 的超大间隔不发生整数溢出；设置恢复有限的刷新频率。
- 修复已有 `async Task` 测试与 Unity Test Runner 的兼容性，使用协程测试等待任务。
- 为 macOS miniaudio 库补上有效的本地签名，避免 arm64 加载时被系统以代码签名错误终止。

## 仍需平台集成验证

这些 EditMode 测试不能证明真实硬件链路正常。发布前仍需在目标平台验证：

1. 首次麦克风授权、拒绝后重试、永久拒绝、应用前后台切换。
2. 实际录音时拔插 USB/蓝牙设备，默认设备变化、断开后的回退和重连恢复。
3. `PlaybackAudioSourceBehaviour` 指定输出端点后，声音确实到达所选扬声器；多组件共享输出时的切换行为。
4. Android AAudio/OpenSL ES、iOS 路由及中断、Windows/Linux 原生后端的实际激活和错误路径。
5. 长时间录放、并发停止与原生回调、内存/句柄增长、实时分配、CPU 峰值及音频失真。
6. 实际 ASR/TTS 模型、AEC 和方向性拾音的端到端质量与延迟。

当前没有生成代码覆盖率百分比，也没有把这些真机验证项计入已通过的单元测试。
